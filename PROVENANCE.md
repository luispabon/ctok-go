# Provenance

This project ports the count reconstruction in Sander Land's ctok v1.3.0,
commit `434612e23c9d9d42d1c5eba23c4761d653e0279d`, under its MIT license.
`REFERENCE.json` records source and dependency SHA-256 hashes. The approved
archive hash identifies the tag codeload archive, not the differently named
commit archive. The tag was checked against the pinned commit before use.

Only the newer V48 family is in scope. Vocabulary witnesses originate from
upstream's measurements; their remaining data provenance uncertainty is not
resolved by this port. No separately licensed evaluation corpora are copied.
This library is unofficial and unaffiliated with Anthropic.

## Unicode oracle

The development-only oracle uses the official digest-pinned Python 3.13.17
linux/amd64 image and regex 2026.8.31. Python category, combining class, case
and NFC behavior use Unicode 15.1.0. The regex Alphabetic and Mark properties
use its Unicode 17.0.0 data. This mixed behavior intentionally matches the
pinned upstream environment rather than selecting the host Go Unicode data.

`tools/reference/generate.py` freezes classification, case mappings and
normalization fixtures. `testdata/unicode/manifest.json` records generator
version, generator and formatted Go output hashes. Official Unicode15.1 NFC
conformance rows are frozen separately under the Unicode data license, not an
upstream ctok evaluation corpus. Ordinary consumer tests require no Python or network.

Invalid UTF-8 is replaced before normalization with `strings.ToValidUTF8(text,
"\uFFFD")`: each contiguous run of invalid bytes becomes one replacement rune.
This is the Go input contract; upstream Python's per-surrogate replacement handles
a different input representation. Literal marker noncharacters remain unchanged
through normalization and are escaped during the later stream construction.

## Normalization fallback

The x/text v0.42.0 differential found that its stream-safe normalization inserts
U+034F on long nonstarter runs, unlike Python NFC. Its build tags also select
Unicode 15.0 or 17.0 tables depending on the Go toolchain. The approved fallback
vendors its maintained normalization composition implementation with generated
Unicode 15.1 tables generated by x/text's maintained generator from the official
UCD archive. `tools/reference/ucd.json` pins the archive, extracted files and table.
The archive pin is independently recorded by Fedora, not published by Unicode.
Offline network-disabled Docker regeneration reproduces the table SHA-256.
`internal/norm/README.md` describes the generator registry addition and the two
NFC-only table edits. BSD LICENSE, PATENTS and the root UNICODE-LICENSE retain
the applicable notices. Unicode License V3 was already the outbound data license
when Unicode15.1 shipped. The retained notice uses its 2023 copyright line;
the release-era text is archived at
https://web.archive.org/web/20230911222703/https://www.unicode.org/license.txt.
The UCD15.1 ReadMe directs users to Unicode's terms of use, which apply V3 to
Unicode data unless a specific restriction is stated.

The approved patch uses growable compact segment storage and stable CCC counting
sort, with no automatically inserted CGJ. Maintained composition, Hangul and
property-decoding logic are retained. `tools/reference/norm_patch.json` records
patched source hashes. Unicode helpers and exhaustive scalar, scalar-plus-mark,
canonical-decomposition and long-run oracle fixtures pass on Go 1.26.10 and
1.27.3. The 500000-mark cases include repeated acute and alternating reordered
marks. Race tests, vet and CGO-disabled build pass for this substrate.

Initial NFC-only 1 MiB benchmarks on AMD Ryzen 9 7940HS linux/amd64, Go 1.26.10:
ASCII 0.93 ms and no allocations; acute marks 66.9 ms and 10.52 MB allocated;
alternating reordered marks 69.2 ms and 14.68 MB allocated. These are single-run
initial measurements, not full-counter performance claims. Full counting parity,
resource gates and independent review remain required before release.
