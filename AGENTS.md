# AGENTS.md

## Overview

ctok-go is a pure-Go, dependency-free library that counts text with the pinned ctok V48 reconstruction. It is not a CLI or service. Runtime code uses no network, subprocesses, credentials, or cgo. Module: `github.com/luispabon/ctok-go`, Go 1.26 (`go.mod`: `go 1.26.0`). The library takes an explicit family, not a model name. Opus-specific behavior is tracked in issue #1.

## Package map

- Root `ctok`: public API (`ctok.go`, `doc.go`) and the count pipeline (`normalize.go`, `stream*.go`, `tiling.go`, `tail.go`, `vocab.go`, `case.go`, `classify.go`, `markers.go`). Its only repository import is `internal/norm`.
- `data/v48.bin`: runtime vocabulary, embedded by `vocab.go`.
- `unicode_tables.go`: frozen Unicode tables, generated by `tools/reference/generate.py`.
- `internal/norm`: NFC code vendored from x/text v0.42.0, plus generated `tables15.1.0.go`.
- `internal/testcorpus`: deterministic authored-input generator for tests. `cmd/export` is a development exporter for the Python oracle.
- `tools/reference`: development-only oracle (Python, Dockerfile) and pins. Go does not build it.
- `testdata/`: committed fixtures and manifests.
- `.github/workflows/checks.yml`: CI.

## Architecture and API invariants

- `Family`, `V48`, `ErrUnsupportedFamily`, `New`, `Counter`, `Counter.Count`, and `Counter.CountContent` are public API. Keep them even when nothing in the repository calls them. Exempt them from unused-export cleanup.
- Only `V48` is supported. `New` returns `ErrUnsupportedFamily` for other values before loading the vocabulary. Vocabulary load errors are wrapped as `ctok: load vocabulary: %w`.
- `Count(text)` equals `CountContent(text) + 6`. `CountContent` excludes framing. Counts are not additive across concatenation.
- Invalid UTF-8: each contiguous invalid byte run becomes one U+FFFD before NFC and the reference's control, space, and private-use normalization. Keep this order.
- `Counter` holds only immutable shared data. Scratch storage belongs to each call. Do not add mutable shared state to `Counter`.
- Measured preallocation in normalization and output is intentional, with growth only as a correctness fallback. Keep it. Resource tests enforce the byte bounds.
- Do not add encode, decode, token-boundary, or model-name APIs.
- Unicode behavior: category, combining class, and NFC follow Unicode 15.1. Regex Alphabetic and Mark follow Unicode 17.0. Case uses pinned upstream exceptions. Do not describe all case behavior as strictly Unicode 15.1.

## Go style and file organization

- Run `gofmt`. Keep non-test code standard-library only. Do not add modules, interfaces, or packages unless the task needs them.
- Keep the root package flat. Put new count logic in the file that owns that stage.
- Do not edit generated files by hand: `unicode_tables.go`, `internal/norm/tables15.1.0.go`, `data/v48.bin`, and generated fixtures.
- Keep attribution in vendored `internal/norm` files, including the Go Authors BSD and PATENTS notices. Update `tools/reference/norm_patch.json` when a patched file changes.
- Keep `LICENSE`, `NOTICE`, `UNICODE-LICENSE`, and the `internal/norm` license files with the code they cover.

## Generated data and provenance

- `unicode_tables.go`: `tools/reference/generate.py` writes it in the Docker oracle, then `gofmt -w` and `finish_manifest.py` update manifests. Commands are in `tools/reference/README.md`.
- `internal/norm/tables15.1.0.go`: x/text generator output for Unicode 15.1.0, finished by `tools/reference/finish_norm.py`. Its SHA-256 must equal `generated_table_sha256` in `tools/reference/ucd.json`. The procedure is in `internal/norm/README.md`.
- A handwritten `internal/norm` change does not by itself change the table hash. Update the source hashes in `norm_patch.json` and only the manifests the change affects.
- `data/v48.bin` and `testdata/vocabulary.json` come from `generate.py vocabulary`. Fixtures under `testdata/parity` and `testdata/unicode` come from the count, stream, API-edge, and Unicode generators.
- Regenerate, repeat, and require identical output before committing. Not every recorded hash is checked by a test or CI step, so verify by regenerating.
- Pins are in `REFERENCE.json`, `PROVENANCE.md`, and `tools/reference/ucd.json`. The oracle is ctok v1.3.0 at `434612e23c9d9d42d1c5eba23c4761d653e0279d`, Python 3.13.17, and a digest-pinned Docker image. Do not run upstream code on the host.
- Do not copy upstream evaluation corpora or other separately licensed data into the repository.

## Testing

- Ordinary tests need only Go and committed fixtures. They must not need Python, Docker, or network.
- A missing required fixture or manifest fails the test. Do not convert it to a skip.
- Keep the independent differential oracles, such as the case implementation in `case_reference_test.go` and the whole-input tiling DP reference, even when they look unused outside tests.
- Resource tests measure bytes and cap allocation. Timing tests are machine-sensitive, and race timings are not performance evidence.
- `TestPerfGuard` needs `-tags perfguard` and is excluded under `-race`. Benchmarks are local diagnostics, not gates.
- Do not add a coverage threshold.
- Prefer a test that reproduces a bug or proves new behavior before the fix.

## Build and check commands

CI runs these on Go `1.26.x` and `stable` (`.github/workflows/checks.yml`):

```sh
test -z "$(gofmt -l .)"
go test ./...
go test -race ./...
go vet ./...
CGO_ENABLED=0 go build ./...
go test -tags perfguard -run '^TestPerfGuard$' -count=1 -v .
```

Local diagnostic, not CI: `go test -run '^$' -bench . -benchmem ./...`. There is no Makefile.

In some local setups, `gofmt -l .` also scans ignored scratch directories. To check only tracked Go files: `git ls-files -z '*.go' | xargs -0 gofmt -l`.

## Change workflow

1. Read `README.md`, `PROVENANCE.md`, and the README for the area you change before editing.
2. Keep the public API and count semantics stable. Changes to counts, framing, UTF-8 replacement, or concurrency need a test and updated documentation.
3. For frozen data, change the generator or source, regenerate with the documented commands, and update only the affected hashes and manifests.
4. Run the narrowest test first, then the full CI commands.
5. Update `README.md` or `PROVENANCE.md` when a pin, hash, count, or measurement changes.
6. Stage explicit paths only. Leave `git status --porcelain` empty after committing.
